# Amor proposal studio

מערכת ניהול פנימית ב-React, Vite ו-Firebase עבור עסק להפקת הצעות נישואין. הממשק בעברית, RTL ומותאם לשני טלפונים ולמחשב. אין כאן שרת מותאם אישית, API או מסד נתונים מקומי: כל הנתונים נשמרים ב-Firebase Firestore.

## התקנה והרצה

```bash
npm install
npm run dev
```

## הגדרת Firebase

1. צרו פרויקט ב-Firebase Console.
2. הפעילו Firestore Database.
3. הפעילו Authentication מסוג Email/Password.
4. צרו ידנית משתמש Firebase יחיד עבור העסק. כתובת האימייל היא פנימית, והסיסמה של המשתמש היא קוד הכניסה העסקי.
5. העתיקו `.env.example` ל-`.env` ומלאו את פרטי אפליקציית Firebase ואת `VITE_BUSINESS_EMAIL`.
6. פרסו את `firestore.rules` ב-Firebase Console או באמצעות Firebase CLI.

קוד הכניסה אינו נשמר בקוד React ואסור לשמור אותו ב-`.env`. המשתמש מקליד אותו במסך הכניסה, והאימות מתבצע באמצעות Firebase Email/Password. כתובת האימייל העסקית אינה סוד ויכולה להופיע בהגדרות frontend.

## מבנה נתונים

הקולקציות הראשיות הן `events`, `equipment`, `packages`, `suppliers`, `locations`. הוצאות ומשימות נשמרות בתוך מסמך ההצעה. מאזיני `onSnapshot` מסנכרנים את הנתונים בין מכשירים בזמן אמת. חוקי Firestore דורשים משתמש מחובר לכל קריאה וכתיבה.

## מסכים

- התחברות בקוד עסקי ושמירת session מקומית של Firebase
- דשבורד עם הצעות, הכנסות ורווחים
- הצעות: חיפוש, סינון, יצירה, עריכה, מחיקה ופרטים
- לוח שנה מתוך תאריכי ההצעות
- ציוד, חבילות, ספקים ולוקיישנים

ההכנות להוצאות ומשימות נשמרות במבנה האירוע וניתן להרחיב את הטפסים בהמשך בלי להוסיף backend.
